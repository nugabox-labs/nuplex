# 아키텍처

## 한 줄 요약
NUPLEX 는 Plex 라이브러리를 **미리 복사해 둔 카탈로그**다. 화면은 Plex 를 호출하지 않는다.

## 데이터 흐름

```
[스케줄]  sync 워커 ──HTTPS──> plex.nugabox.com   (토큰은 여기서만 쓰인다)
              │
              ├─> PostgreSQL     메타데이터 · 시즌 · 에피소드 · 출연진
              └─> ./data/media   포스터 · 배경 · 에피소드 썸네일 (jpg 파일)
                        ↑
[브라우저] ──> web (Next.js, 2620) ──읽기만──┘
     └─ "Plex에서 보기" → app.plex.tv 딥링크 (앱 밖으로 나간다)
```

## 왜 이렇게 만들었나

**지연이 유일한 설계 동기다.** Plex API 를 요청 시점에 호출하면 목록 한 화면에 수십 건의
왕복이 생기고, 포스터까지 실시간으로 끌어오면 NAS 가 그대로 병목이 된다. 그래서 화면이 볼
데이터를 전부 미리 만들어 둔다.

부수 효과 세 가지가 따라온다.

1. **Plex 토큰이 브라우저에 나가지 않는다.** sync 컨테이너 밖으로 토큰이 안 나간다.
2. **Plex 가 죽어도 화면은 뜬다.** 마지막으로 동기화된 상태를 계속 서비스한다.
3. **검색이 DB 질의 한 번으로 끝난다.** Plex 검색 API 를 거치지 않는다.

대가는 **최대 30분의 신선도 지연**이다. 새로 추가한 작품이 홈에 뜨기까지 최대 30분 걸린다.
급하면 `./compose.sh sync` 로 즉시 돌린다.

## 컨테이너 경계

| 서비스 | 포트 | Plex 접근 | DB 접근 | 파일 |
|---|---|---|---|---|
| `web` | 2620 | ✗ | 읽기 | `data/media` 읽기 전용 마운트 |
| `sync` | 없음 | ✓ | 쓰기 | `data/media` 읽기 · 쓰기 |
| `db` | 2621 | ✗ | — | 명명 볼륨 `db-data` |

이 표의 첫 열이 무너지면(= web 이 Plex 를 부르면) 이 프로젝트의 존재 이유가 사라진다.

## 화면 구성

| 경로 | 내용 |
|---|---|
| `/login` | 공통 비밀번호 입력. 유일한 비공개 예외 경로 |
| `/` | 히어로 배너 + 가로 줄(최근 추가 · 그 아래는 Plex 섹션 그대로) |
| `/library/[sectionId]` | 섹션별 목록. 정렬 · 페이지네이션. 첫 페이지 위에 컬렉션 띠 |
| `/collections` · `/collection/[ratingKey]` | Plex 에서 묶어둔 시리즈 모음 |
| `/title/[ratingKey]` | 상세. 줄거리 · 장르 · 감독 · 각본 · 출연 · (시리즈면) 시즌 · 에피소드 |
| `/search` | 제목 · 원제 · 출연진 부분일치 |
| `/media/*` | 동기화가 받아둔 이미지 |
| `/admin/*` | 알림 관리. 별도의 관리자 비밀번호 뒤에 있다 |

상단 메뉴는 **Plex 의 라이브러리 분류를 그대로** 쓴다. 섹션 제목이 `구분 | 하위`
(`영화 | 한국`) 형식이라 앞쪽을 묶음, 뒤쪽을 항목으로 편다. 우리가 새로 묶지 않는다.
안 보일 섹션(음악 · 가족)은 `.env` 의 `EXCLUDED_SECTION_IDS` 로 뺀다 — 코드가 아니다.

모든 페이지는 `dynamic = 'force-dynamic'` 이다 — 빌드 시점에 DB 가 없기 때문이다(AGENTS.md §4).
