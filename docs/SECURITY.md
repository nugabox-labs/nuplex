# 보안

## 위협 모델

이 앱은 **인터넷에 공개된 주소에서 개인 라이브러리 목록을 보여준다.** 지켜야 하는 것은 둘이다.

1. 주소를 아는 아무나가 라이브러리 구성을 보지 못하게 한다 → 공통 비밀번호
2. Plex 토큰이 브라우저 · 저장소 · 로그로 새지 않게 한다 → sync 컨테이너에 가둔다

재생 자체는 Plex 가 다시 인증한다. 이 앱을 뚫어도 영상은 못 본다.

## 접근 제어

**비밀번호 2개.** 계정 개념은 없고, 어느 쪽을 통과했는지만 세션에 남는다.

| 범위 | 환경변수 | 쿠키 | 유효기간 | 쓰는 곳 |
|---|---|---|---|---|
| 열람 | `APP_PASSWORD_HASH` | `nuplex_session` | 30일 | 앱 전체 |
| 관리 | `ADMIN_PASSWORD_HASH` | `nuplex_admin` | 12시간 | `/admin` · `/api/admin` |

**두 값은 반드시 달라야 한다.** 열람용은 지인에게 공유하는 것이라 그걸로 알림까지 보낼 수
있으면 안 된다. 서명 대상에 범위 문자열이 들어가므로 열람용 쿠키를 관리자 쿠키 자리에
넣어도 통하지 않는다. 시도 횟수 제한도 범위별로 따로 센다 — 열람 시도가 많다고 관리자
로그인이 막히면 안 되기 때문이다.

- 평문은 `.env` 를 포함해 **어디에도 저장하지 않는다.** `APP_PASSWORD_HASH` 에 scrypt 해시만 둔다
  (`N=16384, r=8, p=1`, 무작위 salt 16바이트, 키 64바이트)
- 비교는 `timingSafeEqual` 로 한다
- 해시 형식은 `scrypt:N:r:p:salt:key` — 구분자로 `$` 를 쓰지 않는다.
  docker compose 가 `env_file` 값의 `$` 를 변수로 해석해 값을 망가뜨린다(AGENTS.md §4)
- 비밀번호 변경: `npm run hash-password -- '<새 비밀번호>'` → 출력 한 줄을 `.env` 에 넣고 재기동

**시도 제한.** `/api/auth/login` 은 IP 당 10분에 10회까지만 받는다. 컨테이너 하나짜리 앱이라
메모리에 센다 — 재시작하면 초기화되지만 무차별 대입을 늦추는 목적에는 충분하다.

**세션 쿠키.**

| 항목 | 값 |
|---|---|
| 내용 | 범위 + 만료시각 + HMAC-SHA256 서명 (`SESSION_SECRET`) |
| 속성 | HttpOnly · SameSite=Lax · Secure(운영) · 30일 |

담는 정보가 범위와 만료시각뿐이라 훔쳐도 얻을 게 없고, 서명이 없으면 만료시각을 늘릴 수 없다.
`SESSION_SECRET` 을 바꾸면 모든 세션이 즉시 무효가 된다.

**보호 범위.** `proxy.ts` 가 `/login` 과 `/api/auth/login` 을 뺀 전부를 막는다.
**포스터 이미지(`/media/*`)도 막는다** — 포스터만 봐도 무엇을 갖고 있는지 드러나기 때문이다.

## Plex 토큰

- `PLEX_TOKEN` 은 `sync` 컨테이너에서만 쓰인다. `web` 은 Plex 를 호출하지 않는다
- 이미지 요청도 헤더(`X-Plex-Token`)로 인증한다. **쿼리스트링에 토큰을 싣지 않는다** —
  URL 은 로그 · 리퍼러 · 프록시 캐시에 남는다
- 유출 시: Plex 계정에서 해당 기기를 해제해 토큰을 무효화하고 새로 발급 → `.env` 만 교체

## 파일 서빙

`/media/[...path]` 는 경로를 `path.join` 으로 조립하지 않는다. 세그먼트마다
`^[A-Za-z0-9._-]+$` 를 요구하고 `..` 를 거부한다. 어차피 우리가 만든 해시 파일명뿐이라
이 화이트리스트로 충분하고, 경로 탈출 가능성이 아예 사라진다.

## 저장하지 않는 것

- 사용자 계정 · 이메일 · 시청 기록 — 애초에 없다
- 업무 데이터를 localStorage/sessionStorage 에 두지 않는다
- `.env` 는 커밋하지 않는다. NAS 배포 디렉터리에 사람이 직접 올린다
