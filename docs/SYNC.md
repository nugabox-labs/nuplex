# 동기화

`sync` 컨테이너가 주기적으로 Plex 를 읽어 DB 와 `data/media` 를 맞춘다.
코드는 `sync/` 아래에 있다 — `worker.ts`(스케줄) · `run.ts`(흐름) · `upsert.ts`(DB 쓰기) ·
`images.ts`(이미지 저장).

## 두 가지 주기

| 종류 | 기본 주기 | 하는 일 |
|---|---|---|
| 증분 | 30분 (`SYNC_INCREMENTAL_CRON`) | 마지막 성공 이후 `updatedAt` 이 바뀐 항목만 |
| 전체 | 매일 04:00 KST (`SYNC_FULL_CRON`) | 전 항목을 훑고, 못 본 항목을 삭제로 표시 |

증분만으로는 **Plex 에서 지워진 항목을 영영 못 잡는다.** 전체 동기화가 필요한 이유가 그것뿐이다.

> **함정:** 증분 필터(`updatedAt>=`)를 `URLSearchParams` 로 만들면 `>=` 가 퍼센트 인코딩되고,
> Plex 는 그 필터를 **에러 없이 무시한 채 전체를 돌려준다.** 증분이 매번 전체 훑기가 되는데
> 로그만 봐서는 티가 안 난다(멱등이라 결과는 맞다). 처리 건수가 전체 수와 같으면 이걸 의심한다.

기동 시 성공 이력이 하나도 없으면 곧바로 전체 동기화를 한 번 돌린다. 최초 배포 후 사람이
아무것도 안 쳐도 화면이 채워지게 하려는 것이다.

수동 실행:
```
./compose.sh sync          # 증분
./compose.sh sync --full   # 전체
```

## 삭제 감지

행을 지우지 않고 `deleted_at` 을 채운다. 화면 질의는 전부 `deleted_at IS NULL` 을 건다.

- **작품**: 전체 훑기가 **처음 시작된 시각**(`sync_state` 의 `full_sweep_started_at`)을 기준으로,
  그 뒤로 한 번도 안 스친 행을 표시한다. 이번 실행의 시작 시각을 쓰면 안 된다 —
  앞선 전체 동기화가 중간에 끊겼을 때 그때 처리한 항목이 통째로 삭제 표시된다.
  모든 섹션을 끝까지 돈 실행에서만 판정하고, 판정 후 이 키를 지운다.
- **시즌 · 에피소드**: 시리즈 하나를 다시 맞출 때마다 그 시리즈 범위에서 같은 방식으로 표시한다.
  그래서 증분 동기화에서도 에피소드 삭제는 잡힌다.

## 재개

라이브러리가 커서 한 번에 못 끝낼 수 있다. `sync_state` 에 섹션별 진행 위치를 남긴다.

- 키: `cursor:{증분|전체}:{섹션키}`, 값: 다음에 시작할 오프셋
- 페이지(200건)를 다 처리한 뒤에 커서를 옮긴다. 중간에 죽으면 그 페이지를 다시 하지만
  **모든 쓰기가 멱등**이라 결과는 같다
- 섹션을 끝까지 돌면 커서를 지운다

`last_success_at` 도 같은 테이블에 있다. 증분 조회는 여기서 300초를 뺀 시각을 쓴다 —
Plex 와 우리 시계가 몇 초 어긋나도 그 사이 변경분을 놓치지 않게 하는 겹침이다.

## 호출 수를 줄이는 규칙

라이브러리가 1천 편을 넘고 드라마가 많으면 호출 수가 곧바로 문제가 된다.

- 섹션 목록은 200건씩 페이징한다
- **상세(`/library/metadata/{key}`)는 `updatedAt` 이 바뀐 항목만** 다시 부른다.
  안 바뀌었으면 출연진을 다시 받지 않는다
- **에피소드는 시즌마다 부르지 않는다.** `/library/metadata/{key}/allLeaves` 로 시리즈당 1회다
- 출연진은 상위 20명까지만 저장한다. 그 아래는 화면에 안 나온다

## 컬렉션

Plex 에서 사람이 직접 묶어둔 시리즈 모음(마블 시네마틱 유니버스 · 007 …)이다.
**작품을 다 넣은 뒤에** 채운다 — `collection_item` 이 `media_item` 을 참조하기 때문이다.

- 목록은 섹션당 1회(`/library/sections/{key}/collections`)
- 소속 작품은 `updatedAt` 이 바뀐 컬렉션만 다시 받는다. 사람이 손으로 묶는 것이라 거의 안 바뀐다
- 소속은 통째로 지우고 다시 넣는다. 빠진 작품을 따로 찾는 것보다 단순하고 건수도 적다
- 이번에 못 본 컬렉션은 그 섹션 범위에서 삭제로 표시한다

> **함정:** 작품 상세의 `Collection` 필드가 주는 id 는 **컬렉션의 `ratingKey` 가 아니다.**
> 별개의 태그 id 다(실측: 컬렉션 `82755` ↔ 태그 `100432`). 그래서 소속은 반드시
> 컬렉션 → `/children` 방향으로만 채운다. 반대로 맞추려 하면 에러 없이 0건이 붙는다.

## 시청 기록

홈의 "이어서 보기" 가 읽는 자료다(`database/0007_watch_history.sql`).

- `/status/sessions/history/all` 한 곳에서 **모든 사용자의 기록**이 한 번에 나온다.
  항목마다 `accountID` 가 붙어 있어 사람별로 나누는 건 우리 쪽 일이다
- 사용자 목록 **다음에** 받는다 — `plex_account` 행이 있어야 넣을 수 있다
- 마지막으로 받은 시각부터만 받는다(`viewedAt>`). 겹침 5분은 섹션 조회와 같은 이유다.
  실측: 전체 1,972건 → 필터 32건
- 서버 소유자는 Plex 가 로컬 계정 id `1` 로 남긴다. `plex_account` 에는 plex.tv id 로
  들어 있어서, 넣을 때 `is_admin` 계정으로 바꾼다
- 여기서 실패해도 라이브러리 동기화는 계속한다. 홈의 줄 하나가 잠깐 멈출 뿐이다

> **못 하는 것:** 남의 **재생 위치(viewOffset)** 는 관리자 토큰으로 못 얻는다.
> `/library/onDeck` 은 `accountID` 를 조용히 무시하고 관리자 본인의 이어보기를
> 돌려주며(실측), 공유 친구의 토큰은 얻을 방법이 없다. 그래서 "이어서 보기" 는
> "몇 분 남음" 이 아니라 **마지막으로 본 화의 다음 화**다. 영화는 기록에 남았다는 게
> 곧 다 봤다는 뜻이라 줄에 넣지 않는다.

## 이미지

`saveImage()` 가 Plex 사진 트랜스코더(`/photo/:/transcode`)를 거쳐 필요한 크기로만 받는다.
원본을 그대로 받으면 수천 장에서 용량이 몇 GB 로 뛴다.

| 종류 | 크기 | 저장 위치 |
|---|---|---|
| 포스터 | 400×600 | `data/media/posters/` |
| 배경 | 1920×1080 | `data/media/backdrops/` |
| 시즌 포스터 | 300×450 | `data/media/seasons/` |
| 에피소드 썸네일 | 480×270 | `data/media/episodes/` |
| 인물 | 160×160 | `data/media/people/` |

파일명은 **Plex 경로의 sha1 앞 12자**다. Plex 경로에는 갱신 시각이 들어 있어서 아트가 바뀌면
파일명도 바뀐다. 덕분에

- 이미 받은 파일은 건너뛴다 → 재실행이 싸다
- 같은 이름이면 같은 이미지다 → `/media/*` 응답에 영구 캐시를 걸 수 있다

이미지 다운로드는 **실패해도 예외를 던지지 않는다.** 한 장 때문에 동기화 전체가 멈추면 안 된다.
실패한 경우 DB 의 기존 파일명을 유지한다(`COALESCE`).

## 실행 이력

`sync_run` 테이블에 실행마다 한 행이 남는다 — 종류 · 상태 · 처리 건수 · 실패 사유.
화면 하단의 "마지막 동기화 N분 전" 이 이 표를 읽는다.

동기화가 실패해도 기존 DB 는 그대로다. 화면은 계속 뜨고, 다음 주기에 다시 시도한다.
